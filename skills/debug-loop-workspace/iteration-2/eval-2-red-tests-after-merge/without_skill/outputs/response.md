Both tests pass now. Root cause was rounding, not the merge's arithmetic.

## What was failing

```
FAILED tests/test_pricing.py::test_half_cent_rounds_up - assert 1.99 == 2.0
FAILED tests/test_pricing.py::test_order_total - assert 11.99 == 12.0
```

One cause, two symptoms: `order_total` sums `line_total`, so the line error propagated.

## Root cause

`line_total` used `round()` on binary floats. Two problems stack:

1. `0.70 * 3 * 0.95` is not 1.995 in binary float, it is `1.9949999999999997`. Below the tie, so `round(..., 2)` → `1.99`.
2. Even at an exact tie, `round()` is banker's rounding (half-to-even), not the half-up rule billing uses. `round(0.5)` → `0`, `round(2.5)` → `2`.

The tests encode the billing rule: 1.995 bills as 2.00. The code encoded float semantics. `test_no_discount` and `test_whole_cent_discount` passed only because their values happen to be exactly representable.

Assumption I made, since I could not ask: the tests are correct and the intended rule is round-half-up to the cent. That is the standard for currency and matches the comment in `test_half_cent_rounds_up`. I fixed the code, not the tests.

## Fix

`pricing.py` now does the arithmetic in `Decimal` and quantizes to the cent with `ROUND_HALF_UP`:

```python
from decimal import Decimal, ROUND_HALF_UP

CENT = Decimal("0.01")


def _dec(value):
    """Exact decimal for a numeric input (str() avoids binary float artifacts)."""
    return Decimal(str(value))


def _to_cents(amount):
    """Round a Decimal amount to the cent, half-up, as money rules require."""
    return float(amount.quantize(CENT, rounding=ROUND_HALF_UP))


def line_total(unit_price, qty, discount_pct):
    """Price for one order line, in dollars, rounded to the cent."""
    gross = _dec(unit_price) * _dec(qty) * (1 - _dec(discount_pct) / 100)
    return _to_cents(gross)


def order_total(lines):
    """lines is a list of (unit_price, qty, discount_pct) tuples."""
    total = Decimal("0")
    for unit_price, qty, discount_pct in lines:
        total += _dec(line_total(unit_price, qty, discount_pct))
    return _to_cents(total)
```

`Decimal(str(x))` matters: `Decimal(0.70)` would inherit the float error, `Decimal("0.70")` is exact. So the product is exactly `1.995` and half-up gives `2.00`.

Signatures and return types are unchanged — still floats in, float out — so no caller needs touching.

## One thing worth your attention

This changes output for any half-cent value, always by rounding up. If prior billing data was generated by the old code, historical totals will not reproduce exactly under the new code. Worth a look if anything reconciles against stored totals.

Also, `order_total` rounds each line before summing. That is the right behavior for invoices with per-line amounts, and the test agrees, but if you ever want the discount applied to the order as a whole, that is a different calculation — say the word and I will add it as a separate function rather than changing this one.
