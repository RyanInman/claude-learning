## Style grade: report-render

**Grade:** C — Rule 2 (keep the actor visible), Rule 6 (name the specific action and amount), and Rule 9 (attach the reason to every non-obvious rule) cost it the most.

The SKILL.md body passes the Part A checklist cleanly: every step opens with a command verb, the actor is implied by the imperative, and no sentence approaches the tripwire. The frontmatter description (Rule 11) and the input→output example (Rule 12) are exempt zones and were not graded. Every violation lives in `references/formats.md`, where all five sentences break at least one rule — patterned drift concentrated in one reference file.

Quoted offenders for the costliest rules:

- **Rule 2** — "Sections are generated and then they get assembled and then the file is written out." (Generated by what? Assembled by whom?)
- **Rule 6** — "Handle missing metrics as needed." ("Handle" and "as needed" delegate a decision without the information to make it.)
- **Rule 9** — "You MUST NEVER skip the summary section." (ALL-CAPS directive, no reason — a bare rule works only on inputs the author anticipated.)

### Checklist to reach an A

All items apply to `references/formats.md`. Where a fix needs a fact only the author knows, the placeholder is marked in angle brackets — substitute the real criterion or reason, because a vague replacement re-fails Rule 6/9 on the next pass.

1. **Rule 1 (start with a command verb) + Rule 2 (keep the actor visible) + Rule 6 (name the specific action)** — "The template is chosen based on what seems appropriate for the data." → "Choose the template by <the specific criterion, e.g. 'the number of metrics in the export: one metric → single-chart template; two or more → summary-table template'>."

2. **Rule 2 (keep the actor visible) + Rule 3 (one instruction per sentence)** — "Sections are generated and then they get assembled and then the file is written out." → "Generate each section. Assemble the sections in order. Write the report to `report.md`." (This also restores Rule 5 consistency: SKILL.md already names the destination `report.md`, so the reference names the same file.)

3. **Rule 9 (attach the reason; no ALL-CAPS directives)** — "You MUST NEVER skip the summary section." → "Include the summary section in every report, because <the real reason, e.g. 'downstream dashboards parse it and fail on reports without one'>."

4. **Rule 6 (name the specific action and amount)** — "Handle missing metrics as needed." → "When a metric is missing from the export, <the specific behavior, e.g. 'write "no data" in its summary-table row and skip its chart'>."

5. **Rule 5 (one term per concept)** — "The report file is sometimes called the output document or the deliverable." → Delete the sentence. Use "report" everywhere, because it is the term SKILL.md already uses, and offering synonyms invites drift: a reader of "output document" in one place and "deliverable" in another may infer two different files.

Applying all five items (with real values in the placeholders) yields an A on re-review.
