# Notes

- **Partial selection and the manifest scaffold.** `new_manifest.py` writes one entry per unique script name in the classification it is given, so feeding it the full classification would have scaffolded all 5 delegable scripts. I wrote `.delegation-review/classification.picked.json` holding only the picked rows (s1, s3) and scaffolded from that. The full `classification.json` stayed on disk unchanged as the record of the review. SKILL.md does not say how to narrow the scaffold to a subset pick; this is the workaround I chose.
- **Residue question unanswered by the prompt.** The prompt named the rows but said nothing about keeping fixtures in the target, so I took the documented default, "No (Recommended)", and removed `.delegation-review/` after the green run. Nothing extra was written into `changelog-checker/`.
- **The scaffold only covers the happy path.** For a `transform` kind it emits one clean invocation plus a bad-args invocation, so nothing would have exercised the exit-1 branch. I appended a bad-data invocation per script (`expect_exit: 1` plus the finding code) so each failure condition named in the contract has a fixture that trips it.
- **`git status` on the target reports untracked, not modified.** The whole eval workspace is uncommitted, so the Step 0 uncommitted-changes warning did not apply. The `SKILL.md.orig` restore point was still taken.
