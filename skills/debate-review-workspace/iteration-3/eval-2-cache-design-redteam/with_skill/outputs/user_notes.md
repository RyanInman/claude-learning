# User notes — judgment calls and workarounds

1. **Overkill check skipped in favor of proceeding.** SKILL.md's setup step 1 says to offer a single-pass review when the artifact is tiny. The design doc is short, but the user explicitly asked to red-team it with both sides argued properly, and the run is unattended (no questions allowed), so I ran the full debate.
2. **Defender did not author the artifact.** Per the skill, the opening statement says so and presents only the case the document itself makes plus the user's stated concern. Phase 3 answers mark every unmeasured fact "unknown" rather than stipulating plausible values.
3. **Subagent role choice.** Roles.md says to spawn role subagents read-only where the harness supports it; I used the read-only Explore agent type for all seven subagents (2x questions, 2x cases, 2x rebuttals, 1 judge).
4. **HTML-entity unescaping during transcription.** Some subagent replies arrived with angle-bracket text transport-escaped (`&lt;id&gt;`, `&lt;random&gt;`). I restored the literal characters (`<id>`, `<random>`) when transcribing, treating the escaping as packaging, not wording.
5. **Session interruption.** The session was terminated after transcribing the phase-5 rebuttals and before spawning the Judge. On resume I verified the transcript on disk (all phase sections present through phase 5, phase 6 empty) and continued with the Judge phase. Counted as 1 in metrics.json errors_encountered.
6. **Judge report nesting.** The Judge returned a title line and an artifact line above its `##` sections. The standalone final-report.md keeps them verbatim with `##` headings. In the transcript I dropped those two wrapper lines (duplicated by the phase heading and transcript header) and demoted `##` to `###`, per the skill's packaging rule.
